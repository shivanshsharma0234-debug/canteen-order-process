
# Canteen Ordering Process — Requirement & Process Mapping

**Role:** Business Analyst | Self-Initiated  
**Focus:** Requirement Gathering • Process Mapping • Documentation • Jira • Confluence • UI/UX

## Case Study

The objective is to improve a canteen ordering journey by reducing avoidable waiting, improving order-status visibility and creating a more structured workflow for customers and staff.

## What I Worked On

- Defined the business problem and stakeholders
- Mapped the current-state ordering journey
- Identified process bottlenecks and handoffs
- Created business and functional requirements
- Converted requirements into user stories and acceptance criteria
- Structured a Jira backlog
- Designed a Confluence documentation structure
- Created a process-observation analysis template
- Designed a future-state process
- Created a UI/UX concept for the customer ordering journey
- Defined usability and accessibility considerations
- Prepared a stakeholder presentation structure

## BA + UX Workflow

**Discover → Define → Map → Specify → Design → Validate → Recommend**

| Area | Deliverable |
|---|---|
| Business Analysis | BRD, requirements, scope |
| Process | As-Is / To-Be maps |
| Agile | User stories, acceptance criteria, Jira backlog |
| Documentation | Confluence information architecture |
| Data | Excel process-observation analysis |
| UX | User flow, wireframes, design system, UI prototype |
| Communication | PowerPoint case-study structure |

## Design Principles

- Reduce cognitive load
- Make order status visible
- Keep the primary action obvious
- Minimize unnecessary steps
- Design for quick use during peak hours
- Use consistent labels and status states
